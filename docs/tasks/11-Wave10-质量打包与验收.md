## T10-01 埋点与用量统计

| 项 | 内容 |
| --- | --- |
| 覆盖需求 | FR-AI-09；NFR-M-02（关键路径埋点 ≥90%） |
| 优先级 | P1 |
| 前置任务 | T0-09、T0-10、T1-05 |
| 可并行 | T10-02 |

**产出物**

- `packages/core/src/{telemetry-events.ts,telemetry-client.ts}`
- `packages/ai/src/gateway/{usage-report.ts,budget-alert.ts}`
- `apps/renderer/src/features/usage/{UsageDashboard.tsx,BudgetSettings.tsx}`
- 测试

**实现要点**

1. 关键操作埋点（≥90% 关键路径）：项目创建、阶段推进、生成任务、提交、重命名事务、导出导入、登录。**只上报事件名与维度，不含内容**（NFR-M-02 / NFR-S-03）。
2. 用量统计：按 Provider/模型统计 Token 与费用，项目级与全局两级视图。
3. 月度预算告警：设置预算后达阈值（如 80%）告警，超限拒绝并提示。
4. 遥测默认关闭，需显式授权；AI 请求内容默认不上传（复用 T0-10）。

**验收标准**

- [ ] 关键路径埋点覆盖率 ≥90%（列出关键路径清单与覆盖统计）
- [ ] 埋点 payload 中不含任何内容字段（断言测试）
- [ ] 用量仪表盘两级视图数据准确
- [ ] 预算阈值告警与超限拒绝生效

**▶ AI 执行提示词**

```
任务 T10-01：实现埋点与用量统计（packages/core + packages/ai + 渲染层）。
要求：
1) telemetry-events.ts：定义关键事件（项目创建/打开/删除、流水线阶段推进与回退、AI 生成任务开始与结束、Git 提交/推送、重命名事务、导出/导入、登录/登出、错误）与维度字段；**payload 只含事件名、维度 id、耗时、结果状态，严禁包含任何内容、代码、记忆正文、提示词**（写断言测试逐事件校验字段白名单）。
2) telemetry-client.ts：本地缓冲 + 批量上报 + 失败重试；默认关闭需用户显式授权（复用 T0-10）；提供一键清除本地缓冲。
3) 覆盖率：输出关键路径清单与覆盖统计，目标 ≥90%。
4) usage-report.ts + budget-alert.ts：按 Provider/模型/项目/用途统计 Token 与费用（读 usage_record），项目级与全局两级视图；支持月度预算设置，达 80% 告警、超限拒绝并提示（拒绝时给出"本月至今日用量"说明）。
5) UsageDashboard：两级视图切换、按维度分组的图表（调用虚拟化表格与轻量图表，不引重型图表库）、导出 CSV。
6) 测试：字段白名单断言、缓冲与重试、覆盖率统计、用量聚合准确性、预算告警与超限拒绝。
验收：测试通过；输出关键路径埋点覆盖率报告。
```

## T10-02 性能专项优化

| 项 | 内容 |
| --- | --- |
| 覆盖需求 | NFR-P-01 ~ NFR-P-09 |
| 优先级 | P0 |
| 前置任务 | 全部功能 Wave |
| 可并行 | T10-01 |

**产出物**

- `perf/` 基准脚本：`startup.bench.ts`、`canvas.bench.ts`、`memory-search.bench.ts`、`context-assembly.bench.ts`、`rename.bench.ts`、`package.bench.ts`
- `docs/PERF-REPORT.md`
- 优化改动（按需）

**实现要点**

1. 逐项达标：冷启动 ≤5s；500 元素拖拽 ≥50FPS；记忆检索 1000 条 ≤200ms；上下文组装 ≤300ms；内存 Tauri ≤300MB/≤1.2GB、Electron ≤500MB/≤2GB；包体 Tauri ≤60MB、Electron ≤200MB；重命名影响面（1 万行）≤1.5s；重命名事务（≤200 处）≤5s；`.ecpkg` 1 万文件导出 ≤60s、导入 ≤90s。
2. 手段：渲染层代码分割与懒加载、虚拟列表、拖拽层隔离、SQLite 索引与查询计划优化、缓存与增量计算、流式 IO。
3. 每类基准需可重复执行并输出报告。

**验收标准**

- [ ] 九项性能指标全部达标，`docs/PERF-REPORT.md` 含实测数据与机器配置
- [ ] 基准脚本可一键运行（`pnpm perf`）
- [ ] 优化未引入功能回归（全量测试通过）

**▶ AI 执行提示词**

```
任务 T10-02：性能专项优化与基准报告。
要求：
1) 在 perf/ 下编写可重复执行的基准脚本并接入 `pnpm perf`：startup（冷启动到可交互）、canvas（500 元素拖拽 FPS）、memory-search（1000 条记忆检索）、context-assembly（上下文组装）、rename-impact（1 万行工程影响面分析）、rename-execute（200 处变更事务）、package-io（1 万文件 .ecpkg 导出/导入）、memory-footprint（空闲与大型项目内存，分 Tauri/Electron）。
2) 目标（docs/PRD-EveryoneCoding.md §7）：启动 ≤5s；拖拽 ≥50FPS；检索 ≤200ms；组装 ≤300ms；内存 Tauri ≤300MB 空闲 / ≤1.2GB 大型，Electron ≤500MB / ≤2GB；包体 Tauri ≤60MB、Electron ≤200MB；影响面 ≤1.5s；事务 ≤5s；导出 ≤60s、导入 ≤90s。
3) 优化手段（按需，逐一验证收益）：渲染层代码分割与路由懒加载、列表虚拟化、拖拽变换层隔离重渲染、SQLite 索引与查询计划（EXPLAIN QUERY PLAN）优化、记忆与上下文缓存、增量计算、流式 IO。
4) 产出 docs/PERF-REPORT.md：每项含优化前后数据、机器配置、测量方法、未达标项的整改计划。
5) 优化后跑全量测试确认无功能回归。
验收：九项指标出具实测数据；全量测试通过；未达标项有明确整改计划。
```

| 项 | 内容 |

| 优先级 | P0 |
| 前置任务 | 全部功能 Wave |

**产出物**

- 核心模块单测补齐：记忆系统、上下文引擎、Git 封装、Provider 适配、统一标识注册表与重命名引擎、归档读写
- 集成测试：破坏性操作撤销路径全覆盖
- CI 质量门禁配置

**实现要点**

1. 覆盖率：上述六个核心模块 ≥70%（配置 coverage 阈值，低于阈值 CI 失败）。
2. 静态检查：TypeScript strict 零 error；Tauri 版 `cargo clippy` 零 warning；Electron 主进程 eslint 零 error（双形态均需达标，D-01）。

**验收标准**

- [ ] 六个核心模块行覆盖率 ≥70%（输出覆盖率报告）
- [ ] TypeScript strict 零 error；clippy 零 warning；eslint 零 error
- [ ] 破坏性操作撤销路径集成测试 100% 覆盖（列出清单）
- [ ] CI 门禁配置生效，任一不达标则构建失败

| 项 | 内容 |

**产出物**

- Tauri 版：NSIS 安装包 + Tauri Updater 配置与签名

- CI 双通道构建脚本、版本号统一管理

**实现要点**
