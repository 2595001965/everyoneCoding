### 踩坑记录（后续 Wave 必读）

1. **@ec/ui 的 Textarea onChange 是 `(value: string) => void` 不是 event**（Select 同理 1 参、
   无 label prop，用 aria-label）。写错成 event.target.value 会报 "target does not exist on string"。
2. **假端口要同步 machine 指针**：渲染层测试里 saveArtifact 若不调
   `machine.restoreStageState({...state, activeVersion})`，StagePanel 的 effect 依赖
   （activeVersion 值）不变就不重载产物表，表现为"生成了却还显示空态"。
3. **S2 推进语义**：advance() 只把下一阶段置 running；UI 的确认按钮只在 awaiting_confirm 出现。
   测试模拟"设计器产出"要显式 act(() => api.submitForReview('P2'→'S2')) 再点确认。
4. **techChoiceToStack 输出原始 value**（flutter/tauri2），label 仅 UI 展示用——测试按 value 断言。
5. **evaluateImpact 归属链补全**：页面↔所属功能互相牵动（direct 含二者），断言用 toContain 而非全等。
6. **无环图 topoOrder 的无依赖节点相对顺序是实现相关**（Map 插入序），断言用 Set 比较。
7. GenerationQueue 的 failFast 语义：失败即暂停，resume 后重试失败节点（重置 attempts 继续跑）。
8. 子代理并行经验（延续 Wave 3/4）：给它冻结类型签名 + 禁改清单 + 验证命令，产出质量高
   （本次 6 组件零类型错误）；但领域实现的细节语义（如 stack 文本格式）主会话要自己定并在测试锁死。

### Wave 2 遗留 vite build 失败已修复（同日下午）

- 根因：渲染层记忆中心经 `@ec/memory` **根入口**引用 → `domain/memory-item.ts` 值导入
  `newUlid from '@ec/data'` → data 根入口 → migrator/seed（node:fs/path/crypto）→
  rollup 报 `"join" is not exported by __vite-browser-external`。
- 修复：`@ec/data` 与 `@ec/memory` 各加 `exports.browser` 条件入口（对齐 @ec/ai、@ec/pipeline）：
  - data/browser.ts 只导出 `ids.ts`（newUlid/nowMs/ulidTime 纯函数）；
  - memory/browser.ts 导出 domain/*（scope/memory-item/conflict/inheritance）+
    4 个 service 分区常量（FEATURE/ISSUE/PAGE_SECTION_LABELS、PROJECT_SECTION_TITLES——
    service→repo 全是 import type 擦除，运行时只依赖 domain + data/browser 的 newUlid）+
    repo 层纯类型 `export type { MemoryPatch, ChangeLogRecord }`（编译期擦除零运行时依赖）。
- 结果：vite build 402 模块通过（主包 593KB / gzip 195KB），4 包 tsc 零错误，
  全仓 129 文件 1259 测试零回归，eslint 零问题。
- 教训：**rendering 层引用 workspace 包时 tsc 绿灯不代表构建能过**（tsconfig paths 映射
  与 Vite exports 解析是两套）；新包接入渲染层要立即跑一次 `vite build` 探针。
  且 `export type { X } from './node-side'` 是把 Node 侧类型安全暴露给浏览器层的关键手段。
