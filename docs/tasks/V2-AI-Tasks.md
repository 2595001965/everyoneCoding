# EveryoneCoding V2 — 可直接交给 AI 的工作任务

> 日期：2026-10-01。需求依据：[第二版 PRD](../PRD-EveryoneCoding-V2.md)。本清单面向已有仓库的增量实现，不是从零重写。
>
> 共 25 个任务，初始状态均为“待办”。代码入口是编写时已定位的阅读起点，不代表能力已经完成；执行时必须核验当前工作区。本文不授权自动推送、上线、充值、删除用户数据或使用真实付费模型。

## 1. 使用方式

### 1.1 直接复制这一段即可开始

```text
请在 EveryoneCoding 仓库执行 V2-T01。
先完整阅读 docs/PRD-EveryoneCoding-V2.md，再阅读 docs/tasks/V2-AI-Tasks.md 的通用约定及 V2-T01 卡片。
按当前工作区核验，不依据旧任务状态假定已完成。只执行本任务，不顺手实现后续任务。
先检查 git status，保留所有已有修改；若存在真正需要用户决策的阻塞，说明影响，其余按任务卡实施并验证。
完成后报告修改文件、验收结果、实际测试命令、未验证事项与后续依赖。不要自动提交、推送或发布。
```

后续把 `V2-T01` 替换为目标编号即可；也可直接复制各卡片最后的专用提示词。提示词要求 AI 读取本文件，所以不需要每次手贴全部通用上下文。若 AI 无仓库访问权限，必须同时提供 PRD、通用约定、目标卡片和相关源码，不能只提供任务标题。

### 1.2 通用执行约定（全部任务强制继承）

1. **范围**：只实施当前任务及其必要接线/测试，不把本清单理解为一次自动执行 25 项。已有可用能力优先扩展，避免另写第二套 Provider、数据库、窗口管理或 AI 网关。
2. **现状**：读取 `git status`、相关源码、根 `package.json`、`.workbuddy/memory/MEMORY.md` 和相关 details；历史日志只作线索，以实际文件与测试为准。路径按当前仓库根解析，不照搬旧文档中的 D 盘或其他用户名路径。
3. **保护已有工作**：本仓有大量未提交修改。不得 reset/clean/stash/还原或批量覆盖来获取“干净环境”；遇到同文件并行改动先协调。仅修改与当前任务相关的行，不全仓格式化。
4. **架构**：业务契约放共享层，Node/SQLite/AST/文件系统在宿主或服务端，renderer 经 shell-api 使用；同步 Electron 的白名单/桥接/域装配，以及 Tauri bridge/Rust/sidecar 边界，不能靠只补 UI 假接口交付。
5. **产品规则**：保留 V1 未被 V2 替换的功能；源码是真实来源；客户端代码视图只读；AI 修改必须走补丁、确认、版本校验和可恢复事务。导入工程不得强制转换 DSL。
6. **Provider 中立**：继续支持已有协议，不把多 Provider 需求变成单厂商接入；同名 Model 不同 Provider 的路由、价格、限制和历史必须独立。
7. **安全**：不读真实 Key/凭据内容用于调试，不将密钥带入日志/记忆/前端；陌生源码只读扫描，执行依赖/命令前确认。涉及外部请求、真实数据库迁移和付费推理先取得授权。
8. **并行实施**：只有依赖已完成且写集不重叠的任务可并行。共同迁移文件、shell-api、导出入口、注册表与锁文件由一名集成人协调；不得让多个 AI 同时改同一工作目录。若用户允许并行写任务，先约定各自独立分支/工作副本及合入负责人。
9. **测试**：先基线、后针对性测试，再相关回归。逻辑可用确定性夹具；账务/锁/文件恢复需真实资源集成测试。UI 要实际操作；原生窗口/IPC 要真实外壳验证。用 mock 跑通不能宣称真实 Provider 或双外壳已验证。
10. **真实结果**：未运行、缺环境、已有失败、新增回归分别报告。不伪造 Token、价格、创建时间、账单余额、模型支持或测试截图。
11. **粒度**：卡片是一项可验收工作单元，不保证一个上下文窗口完成；过大时按列出的交付物拆子任务，保留依赖和验收，不用 TODO/mock 替代生产接线后宣称完成。
12. **交付**：不自动提交/推送/部署。当前任务的说明、测试及必要契约文档可一并修改；更新本清单状态须串行进行，不改旧任务表宣称 V2 已完成。

### 1.4 完成定义与回报格式

“已实现”表示代码和针对性测试完成；“已验收”表示卡片验收条件有证据，包括真实 UI/外壳条件。不能把二者合并。

```text
任务：V2-Txx
状态：待办 / 进行中 / 已实现待验收 / 已验收 / 阻塞
修改：路径 + 关键变化
验收：逐项通过/失败/未执行及证据
验证：实际命令、环境、结果
边界：未支持范围、依赖状态、未决问题
后续：可以开始的任务；不自动继续执行
```

## 4. 详细任务卡

### V2-T01 — 核验基线并建立公共契约

- **覆盖**：PRD §2、§11、§12、§13；为所有新需求提供契约基础。
- **入口**：根工程配置、shell-api、data migrations、现有 project/ai/preview 领域及双外壳装配。
- **交付**：现状/缺口简表；公共实体和事件 schema；迁移顺序与领域边界；后续任务可引用的契约文件和最小序列化测试。新增后端网站/账务的目标位置必须标记为拟新增。
- **实施**：
  1. 区分已实现、只有类型/假端口、未实现、需替换；核验真实生产链路而非只看测试。
  2. 定义 ProjectSource/Detection、RuntimeInstance、ElementAnchor、ApiEndpoint/Relation、ProviderModel、UsageAttempt、Session/Task、ChangeSet、PriceVersion/账务接口。
  3. 固化 ID、版本、时间、未知值、事件去重和错误语义；在共享层避免 Node 运行时依赖。
  4. 明确数据库迁移 owner、文件分工和后续服务边界；只追加当前必要迁移，不一次建立空壳数据库全集。
- **验收**：类型检查/契约往返测试通过；renderer 能安全导入；同名模型、多服务同路径接口、未知计量数据不会在契约层被压扁；列出阻塞业务项但不代替用户决定真实售价。
- **不做**：一次实现六项业务、重写旧架构、删除现有能力。

```text
执行 V2-T01。阅读 docs/PRD-EveryoneCoding-V2.md 与 docs/tasks/V2-AI-Tasks.md 的通用约定和本卡。
核验当前生产链路，建立源码/接口/路由/计量/会话/账务公共契约及迁移边界；提供可编译类型、schema和最小测试，不要只写空泛架构建议。
保留已有未提交修改，不提前实现其他任务；报告可复用模块、真实缺口和后续写集分工。
```

### V2-T02 — Provider+Model 复合身份与数据迁移

- **覆盖**：V2-MDL-01/02/03/06；PRD §11、§13。
- **入口**：provider-repo、model-repo、purpose-binding、ai-control-api、远程配置 applier、data migrations、ProviderSettings。
- **交付**：复合路由键/唯一约束、默认与用途绑定迁移、目录来源区分、历史映射及选择器适配。
- **实施**：扫描所有仅依赖 modelId 的查询、缓存、引用和序列化；明确 providerModelId 与官方 canonicalModel 的职责；从旧外键迁移，不猜历史未知 Provider。
- **验收**：创建 A/B 两个 Provider 并使用同 modelId，独立保存/编辑/删除模型、绑定用途、选择默认路由；重启后不混淆；迁移可回滚，历史保留 unknown；远程刷新不覆盖本地配置。
- **边界**：费率版本由 T17 实现，本任务只保证路由身份正确。

```text
执行 V2-T02。先读 docs/PRD-EveryoneCoding-V2.md 和 docs/tasks/V2-AI-Tasks.md 的通用约定及本卡，确认 T01 契约可用。
把 Provider+Model 身份贯穿存储、用途绑定、默认配置、远程配置和选择器；迁移真实旧数据，不把同名模型合并。
用 A/B Provider 同 modelId 的持久化和迁移测试证明不串路由，不顺手实现平台计费。
```

### V2-T03 — 免平台登录的本地 Provider 完整闭环

- **覆盖**：V2-MDL-04/05/07；V2-E2E-01/12。
- **入口**：ai-control-api、AI runtime、AuthClient、renderer runtime/ai-settings 与 ProviderSettings。
- **交付**：明确本地/平台模式、本地首次使用路径、BYOK 请求链路、凭据与连接测试流程。
- **实施**：去除本地 AI 操作对平台登录/余额的隐式依赖；平台失联/退出只影响平台能力；保留本地配置，直连在安全宿主执行，连接对话测试先提示可能收费。
- **验收**：空用户数据域不注册平台即可创建 Provider；禁止平台域名网络访问时仍可向授权测试上游生成；日志无 Key；平台余额 0 不阻断 BYOK；登出不删除配置。
- **边界**：真实付费测试必须授权；受控上游结果明确标模拟。用量记录先接现有接口，T11 统一升级。

## 6. 最容易出现的“看起来完成，实际上没完成”

- 源码导入仍要求私有 manifest，只是把 `.ecpkg` 改为 `.zip`。
- 预览显示设计 DSL 或 Mock 截图，而不是工程真实运行页面。
- 选到 DOM 就编造文件行号，或只用浏览器临时插入新按钮。
- 接口扫描只读 OpenAPI/apiDeps，不展示真实源码证据和未解析范围。
- 按文件 mtime 排序却标“接口创建时间”。
- Model 同名仍覆盖另一个 Provider，或用模型名查到别的渠道价格。
- 平台停服导致自定义 Provider 不可用。
- 实时速率直接数 SSE chunk；缓存 Token 加两遍；上下文占用等于全部历史消费。
- 流中估算和最终 usage 各记一份；三窗口观察同请求扣三次费用。
- 网站“钱包”是前端可编辑数字，或者用客户端上报费用直接扣款。
- 开三个窗口实际只有一个任务轮流运行，或三个 Agent 都直接写同一目录。
- Git worktree 忘记用户未提交改动，合入/回滚时覆盖后续变更。
- Electron 能用就称 Tauri 也完成，或把缺失环境当测试通过。

上述任一情况都不能标记对应任务“已验收”。
