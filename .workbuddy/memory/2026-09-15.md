### 关键环境坑（会持续遇到，务必记住）

- **`ELECTRON_RUN_AS_NODE=1`**：WorkBuddy / VS Code 这类自身基于 Electron 的宿主终端会注入它，
  导致 `electron.exe` 退化成纯 Node（`require('electron')` 只返回路径字符串、`app` 为 undefined）。
  **启动 Electron 前必须从子进程环境删除它**，否则报错极具误导性（看起来像代码 bug）。
- **无 GPU 宿主**：此类环境 Electron 的 GPU 进程会反复崩溃并以
  `GPU process isn't usable. Goodbye.` 退出，需 `--disable-gpu --disable-software-rasterizer --no-sandbox`。
  已由 `scripts/dev.mjs` 自动检测（启发式：`ELECTRON_RUN_AS_NODE` 存在）。
- **`better-sqlite3` ABI 两套共存**（关键设计，勿破坏）：
  - Node 侧（vitest）用 `.pnpm/better-sqlite3@*/…/build/Release/`
  - Electron 侧放在 `apps/desktop-electron/build/Release/`（esbuild 内联后 `bindings` 的 module_root
    解析为应用根，该路径正是候选之一）
  - **切勿用 Electron 版覆盖 `.pnpm` 那份** —— 会弄坏全仓单测基线。
  - ABI 号用 `ELECTRON_RUN_AS_NODE=1 electron -p process.versions.modules` **动态探测**（本机 =130），
    不要硬编码映射表。
- **Git Bash 的 GNU tar** 会把绝对路径盘符误判为 `host:path`（`Cannot connect to D:`）——
  传相对路径 + `cwd` 规避。
- **Git Bash 会把 `/c/...` 当 Windows 相对路径转换**（变成 `D:\c\Users\...`），
  调 Windows 程序时要用 `C:/...` 形式。
- pnpm 需经 corepack 调：`node "<node24>/node_modules/corepack/dist/pnpm.js" install`；
  nvm 的 `pnpm.exe` 在非交互环境报 `CommandNotFound`。

## 桌面启停脚本（`scripts/start-desktop.bat` / `scripts/stop-desktop.bat`）

主人要「桌面版启动、终止脚本」。产出一对 `.bat`，全部写死绝对路径，不依赖 PATH 与 pnpm shim，双击即用。

### 脚本设计

- `start-desktop.bat` 四步：① 起渲染层 5173（已在监听则跳过）→ ② `curl` 轮询到就绪 →
  ③ 起 Electron（走 `apps/desktop-electron/scripts/dev.mjs`，不绕开）→ ④ 自检 `electron.exe` 进程数。
  另清掉 `ELECTRON_RUN_AS_NODE`（宿主会注入）。
- `stop-desktop.bat` 三步：① 按窗口标题 `EC-Renderer` / `EC-Electron` 结束 → ② 结束 `electron.exe` →
  ③ 结束占用 5173 的 PID；末尾按端口重新校验，给出确定性结论。

| --- | --- | --- |
| 执行前 | LISTENING(1) | 5 |
| 终止脚本执行中 | 结束 5 个 electron、结束 PID 7260 | — |
| 执行后 | 0 | 0 |

启动脚本日志同样完整：`OK：http://127.0.0.1:5173 已就绪` → `OK：检测到 1 个 electron.exe 进程` → `启动完成`。

### 踩坑（本轮最大成本，务必记住）

1. **`.bat` 编码**：中文 Windows 必须 **GBK(cp936) + CRLF + 无 BOM**。先试过 UTF-8 + `chcp 65001`，
   cmd.exe 解析多字节字符会错位（把注释文字当命令执行，报 `'2)' is not recognized`）。
2. **编码转换只能单向、单次**：正确链路 = `Write(UTF-8)` → `node 规范 CRLF` → `iconv -f UTF-8 -t GBK`。
   本轮两次把中文写坏：用 Read/Write 工具往返 GBK 文件（Read 按 UTF-8 解 GBK → U+FFFD → 转码成满篇 `?`）；
   用 PowerShell `ReadAllText(UTF8) + WriteAllText(936)` 实测产出 829 个 `0x3F` 字节。
   验收口径：GBK 解码汉字数与源件一致、`0x3F` 计数为 0、无 U+FFFD、无孤立 LF。
3. **测试宿主的进程回收**：工具调用结束会回收子进程树，`start` 出的窗口留不住；用 `run_in_background`
   起 vite/Electron 才能跨调用存活。`| Out-String` 会因子进程继承管道而挂死，`*>` 重定向到文件才对
   （PS 5.1 写 UTF-16LE，读取须按该编码解）。
4. **`tasklist /V` 会被安全策略终止**（bash→node→cmd 链路下尤甚）；`taskkill /FI "WINDOWTITLE eq ..."`
   安全但**无匹配也返回 0**，不能当成功判据 —— 脚本因此改为「第 1 步不报战果，确定性战果由进程数/端口给出」。
5. `cmd.exe` 无法从 bash 直接调用（被策略拦），PowerShell 路径可用；safe-delete 钩子在单次批量删
   5~6 个文件后会终止进程，清理必须分小批次。

## 修 Electron GPU 崩溃（主人实测报 `GPU process isn't usable. Goodbye.`）

主人在普通终端跑桌面端时，GPU 进程反复崩溃并以 FATAL 退出。

### 根因

`apps/desktop-electron/scripts/dev.mjs` 的 GPU 降级只靠启发式：

```js
function isEmbeddedHost() {
  return process.env['EC_ELECTRON_HEADLESS'] === '1' || process.env['ELECTRON_RUN_AS_NODE'] !== undefined;
}
```

从**普通终端**（独立 cmd、双击 .bat）启动时两个变量都不存在 ⇒ 判定"有 GPU" ⇒ 不加降级开关 ⇒
GPU 进程连续崩溃（达到 gpu_data_manager 重试上限）⇒ FATAL。启发式天然覆盖不了
"远程会话 / 驱动异常"这类无 GPU 场景，必须靠失败兜底。

另有一个自己埋的坑：`start-desktop.bat` 里写了 `set "ELECTRON_RUN_AS_NODE="`，
**反而把 dev.mjs 唯一可靠的判据抹掉了**。

### 修复（两处）

1. `dev.mjs` 改**两层兜底**：① 启发式直接软件渲染；② 首轮若嗅到 GPU 崩溃特征
   （`GPU process isn't usable` / `gpu_process_host.cc` / `GPU process exited unexpectedly`），
   自动带 `--disable-gpu --disable-software-rasterizer --no-sandbox` 再启一次。
   为此把 stderr 由 `inherit` 改为 `pipe`（透传 + 保留尾部 16KB 窗口做嗅探），`main` 改为 async。
2. `start-desktop.bat` 删掉那行清理语句，改为注释写明"故意不清除"；
   同时把第 4 步自检从"瞬时计数"改成"计数非 0 后等 3 秒复查"。

### 验证（真实复现 + 回归）

- 复现：`env -u ELECTRON_RUN_AS_NODE -u EC_ELECTRON_HEADLESS node scripts/dev.mjs`
  （本机沙盒同样无 GPU）→ **完整重现主人那串报错直到 FATAL** → 随即打印
  `[dev] GPU 进程崩溃，改用软件渲染重试` → 第二次启动 5 个 electron.exe 稳定存活 45s 以上。
- 启动脚本端到端四步全过。自检修好前报"检测到 3 个"（抓到崩溃前那批瞬时进程），
  修好后报"检测到 5 个"（与稳态一致）。
- `eslint apps/desktop-electron/scripts/dev.mjs` 零问题。

### 补丁手法（GBK 文件不允许直接编辑）

`.bat` 是 GBK，**不能**用编辑器或 Read/Write 工具直接改。做法：一次性 mjs 脚本走
`iconv -f GBK -t UTF-8` → 字符串替换（带断言，找不到目标就抛错）→ `iconv -f UTF-8 -t GBK` 写回，
末尾做字节级验收（汉字数、`0x3F` 计数为 0、无 U+FFFD、无孤立 LF）。两次补丁均通过。
