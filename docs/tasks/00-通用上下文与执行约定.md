## 1. 怎么用这份清单

### 1.1 三条使用规则

1. **先铺 P 块，再投任务**：任何任务提示词执行前，先把 §2「通用上下文块 P」完整贴给 AI（或让它读取本文件），再贴任务卡片末尾的「▶ AI 执行提示词」。这样任务才是自包含的，AI 不需要回头问背景。
2. **严格按 Wave 顺序推进，Wave 内可并行**：Wave N 的任务只依赖 Wave ≤ N 的产出。同一 Wave 内标注「可并行」的任务可以同时开多个 AI 会话。
3. **一个任务 = 一次 AI 会话**：任务粒度按「单会话可完成并自测」设计。若 AI 在一个任务里产出过多文件、无法一次自测通过，说明要再拆，请拆完再执行。

> 以下内容复制给 AI，作为所有任务的固定前置。

```
【项目】EveryoneCoding —— Windows 桌面端 AI 全栈开发工作台（闭源项目，不开源、不使用开源许可证、不写 LICENSE、不写"欢迎贡献"类文案）。
核心链路：需求 → 界面 → 技术文档 → 代码，靠五层记忆 + S1–S7 流水线驱动，全程可视化、可回退、可定点修改。

【目标平台】客户端本体：Windows 10 1809+ / Windows 11，x64（ARM64 为 P2）。
【产物目标端】七端：Web（原生网页）/ Android / iOS / HarmonyOS（鸿蒙）/ Windows / Linux / macOS；多端技术方案矩阵见 PRD FR-AI-13——Web 默认 React，移动双端默认 Flutter（单代码库），鸿蒙用 ArkTS + ArkUI，桌面三端默认 Tauri 2（单代码库）。

【形态】Tauri 2 与 Electron 双形态并存、功能等价（D-01）。业务逻辑不得感知外壳差异，一律通过 Shell API 抽象调用。

【技术栈】
- 渲染层：React 18 + TypeScript（strict）+ Vite（同时作为 Electron 渲染层与 Tauri WebView 层）
- 状态：Zustand + Immer + Zundo（patch 级 undo）
- 画布：DOM + CSS Transform（不用 canvas，保证与最终 Web 产物零失真）；拖拽 dnd-kit
- 本地存储：SQLite（FTS5 + sqlite-vec），仅本地，无云端同步
- Git：git2(libgit2) 优先，回退系统 git CLI
- AI：自研 Provider Adapter，OpenAI / Anthropic 双协议
- 预览：内置 Mock Server + 子进程托管真实后端
- 多端产物生成：按 FR-AI-13 七端矩阵（D-03，必须真实生成可编译工程；每端生成后强制编译校验，环境缺失时输出引导与待验清单）
- 代码视图：只读（见硬约束）
- 打包：Tauri Updater / electron-updater，均出 NSIS 安装包

【工程目录约定】
apps/desktop-tauri/     Tauri 2 外壳（Rust）
apps/desktop-electron/  Electron 外壳（Node 主进程）
apps/renderer/          React 渲染层（双形态共用）
packages/shell-api/     外壳抽象接口 + 工厂 + mock
packages/core/          事件总线 / 命令系统 / 撤销重做 / 设置 / 日志
packages/data/          SQLite 迁移、DAO、FTS5 与向量检索
packages/ui/            设计令牌 + 基础组件库
packages/memory/        记忆领域层（五层模型、检索、自动抽取）
packages/designer/      PageDSL、画布、组件库、属性面板
packages/ai/            Provider 适配、上下文引擎、代码写入管线
packages/pipeline/      S1–S7 状态机与阶段产物
packages/git/           Git 封装
packages/preview/       Mock Server + 后端进程托管
packages/registry/      统一标识注册表 + 重命名引擎
packages/package-kit/   .ecpkg 归档读写
packages/account/       账号客户端 + 云端最小服务

【硬约束（违反即返工）】
1. AI 是代码与数据库脚本的唯一写入口：客户端代码视图只读，不提供任何手动编辑入口；外部编辑器改动必须被检测到并提示（FR-AI-11 / D-04 / D-08）。
2. 数据本地优先：项目、记忆、文档全部本地；云端仅承担账号注册登录（D-02）。不做云同步、不做云端分享链接、不提供平台运营的远程配置服务（D-06 / D-09）。
3. 不跨项目自动联动：重命名与记忆更新仅项目内生效（D-07）。
4. 中文命名策略：组件名与标识符用英文或拼音，显示文案保留中文（D-10）。
5. 全部操作可视化：系统不依赖任何命令行输入，Git/依赖安装/构建/运行全部由 UI 触发并回显结构化日志（FR-SET-08）。
6. 破坏性操作必须二次确认 + 可撤销；所有写文件用"临时文件 + 原子替换"。
7. 敏感数据（Token / API Key / 连接串）一律 DPAPI 加密存储，日志与导出自动脱敏，明文 Key 永不落盘日志。

【代码与交付约定】
- TypeScript strict 零 error；组件与标识符英文/拼音，注释与日志中文。
- 每个任务必须给出：新增/修改的完整文件路径、关键实现说明、单元测试（核心逻辑 ≥70% 覆盖）、以及如何自测。
- 不修改与本任务无关的文件；不引入未在本任务列出的重依赖（如需新增依赖必须先说明理由）。
- 提交信息遵循 Conventional Commits。
- 需求细节以 docs/PRD-EveryoneCoding.md 为准；若需求与本上下文冲突，以 PRD §2.2 已确认决策为准。
```
