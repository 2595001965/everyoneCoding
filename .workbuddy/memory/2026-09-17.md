### 关键实现决定

- **`DocMemoryPort` 为什么由本域实现**：它是**文档域自己定义的端口**，要求外壳提供
  "记忆节点读写 + 文档-记忆关联"。`@ec/memory` 的完整服务（向量检索、变更日志、结构化版本）
  未装配，故按端口契约直接落 `memory_item` / `memory_doc_link`。
  **不生成 embedding**（关键词检索正常、向量检索跳过），不改 `memory_change_log`；
  记忆域装配后应把本实现替换为委托其服务。这是"装配端口"，不是"另起一套算法"。
- **`previewConvertToMemory` 不注入 `MemoryExtractionPort`**：`DocService` 在缺端口时会抛
  `extraction_unavailable` 并且**自带给用户看的中文话术**（"请在设置中配置 AI 中转…"），
  路由层保留原文案、只把 code 映射成 `NOT_SUPPORTED`。
  `commitConvertToMemory`（提交已编辑草稿）不依赖 AI，可用——这一对方法的差异要在文档里写清。
- **`importFromFile` 的分流**：markdown/txt 按 utf8 读字符串，docx/pdf/image 读字节；
  来源文件路径记进 `sourceRef` 以便溯源。
- 错误映射：`DocDomainError` 的 6 个 code → `ShellErrorCode`
  （not_found→NOT_FOUND，empty_content→INVALID_ARGUMENT，其余→NOT_SUPPORTED），**保留原 message**。

### 顺带修掉的一个真实缺陷（在 core 里）

`createDefaultParserRegistry()` 的 `supported()` 会**把 image 也列进去**，
但未注入 OCR 端口时 image 解析器只能在解析阶段报"暂不支持"——
于是 `supportedFormats()` 会让导入界面给出一个**必然失败的选项**，
而该函数与注册表自身的 JSDoc（"image 未注入 OCR 端口时解析如实报'暂不支持'"）相互矛盾。

**远端内容是对的（`ls-remote` 与本地 HEAD 均为 1cf157d），问题只在本地引用存储。**

**根因：D 盘卷层面的文件过滤驱动拦截，与仓库本身无关。**

判据链（按发现顺序，每一步都排除了一个假设）：

1. `git update-ref refs/remotes/origin/x HEAD` → **exit 0、零报错、文件不存在**；
   更反常的是它会把 `refs/remotes/origin` **整个目录删掉**（正常应往里写文件）。
2. `.git/logs/refs/remotes/origin/main`（reflog）**写成功且内容正确**（`... afde6b8 ... update by push`），
   唯独 ref 本体丢失 → 说明事务执行到了 reflog 这一步，不是"git 没跑"。
3. **路径特异性**：`refs/heads` 存活 5/5、`refs/tags` 5/5、`refs/remotes/origin` **0/5**。
4. ACL 与 `refs/heads` 完全一致、无重解析点、非只读；无活动 hooks、无 `core.hooksPath`、无 alias；
   Defender 受控文件夹访问未启用。
5. `core.fscache` 假设被证伪（`-c core.fscache=false` 同样复现）。
   ⚠️ **踩坑**：第一次对照实验把 `-c` 写在子命令后面（`git fetch -c core.fscache=false`），
   报 `unknown switch 'c'`，等于没测——**`-c` 必须写在子命令之前**。
6. **跨仓库/跨盘符判别（决定性）**：全新仓库中 C 盘 `%TEMP%` 存活 3/3，
   D 盘（同盘不同目录、仓库父目录）**0/3** → 排除"仓库坏了"，锁定 D 盘。

**嫌疑对象**：机器同时运行 **Avast**（`aswidsagent.exe` / `aswengsrv.exe` / `avastsvc.exe`）、
**360 安全卫士**（`360tray.exe`）、Windows Defender，三者均带文件过滤驱动。
（主人这台机器此前已有 Avast 接管明文 DNS 的先例，见 `web-access-layer-diagnosis` 技能。）

**修复路径（需主人操作）**：在 Avast 与 360 中为 `D:\code`（或整个 D: 开发目录）添加
文件/文件夹排除项，重启后重跑探针确认。**不能靠改 git 配置绕过，那是治标。**

**已做的临时处置**：用 Python 直写 `.git/refs/remotes/origin/main`（该路径可被 Python 正常写入），
恢复后 `git status -sb` → `## main...origin/main`、`branch -vv` → `[origin/main]`，三方一致。
**下游任何 `git fetch`/`push` 会再次清掉此引用。** 因 `branch.main.remote/merge` 已配置，
`git pull` / `git push` 不受影响。
