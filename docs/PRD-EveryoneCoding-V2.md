## 1. 产品目标与范围

### 1.1 产品定位

EveryoneCoding 从“以设计器生成新项目的 AI 工作台”扩展为“可接管现有源码的可视化 AI 全栈开发工作台”。用户导入普通工程后，可以运行真实前端、选中页面元素、查看前后端接口关系，让多个 Agent 在隔离环境中实施可审查的修改，并实时了解用量和费用。

新建项目仍支持 V1 的需求、设计、技术文档、代码生成七阶段流程；导入现有工程不强迫用户重新走一遍生成流程，也不要求源码转换为页面 DSL。

### 1.2 六项需求与交付目标

| 用户需求                                                          | 本版目标                                                 | 核心编号            |
| ----------------------------------------------------------------- | -------------------------------------------------------- | ------------------- |
| 导入源码，取消自定义格式，自动渲染前端                            | 普通目录、Git、标准 ZIP 接入；识别工程并托管真实运行环境 | `V2-SRC`            |
| 自动识别后能选中 HTML 元素                                        | 运行预览中的 DOM 选取、源码定位、上下文附加与 AI 修改    | `V2-DOM`            |
| 识别前后端接口、分类/排序、指定位置增删接口、依接口新增功能或元素 | 可追溯的接口索引和双向开发入口                           | `V2-API`            |
| 服务端网站、Provider 差异定价、无服务端自定义、同模型多 Provider  | 平台托管与本地直连并存，模型路由标识不冲突               | `V2-MDL`、`V2-WEB`  |
| 实时速率/缓存/会话/上下文与用量、金额、余额                       | 分清实时估算、最终用量、估算成本、平台实扣和可用余额     | `V2-USG`、`V2-BILL` |
| 多窗口 Agent 并发                                                 | 独立会话、共享调度、隔离工作副本、受控合入、统一预算     | `V2-AGT`            |

### 1.3 范围与优先级

- **P0**：V2 核心闭环必需；六项方向的基础闭环均属于 P0。
- **P1**：扩展框架、便利功能和运营自动化，不应阻塞基础闭环。
- **P2**：后续规划，不应被实现 AI 自动扩充为当前任务。
- 不承诺一次识别所有语言/框架；必须公开支持矩阵并展示实际识别结果。
- 多窗口是同一用户在本机运行多个 Agent，不等于多人实时协作，也不包含云端代跑代码。
- 服务端网站负责用户中心、模型服务、定价、账务和管理，不把桌面设计器整套迁移成浏览器 IDE。
- 保留七端产物生成，但本次 HTML 选取仅覆盖存在 DOM 的 Web 页面/WebView 页面，不把原生 Flutter/ArkUI/Qt 控件伪装成 HTML 元素。

### 2.3 贯穿全局的规则

1. **源码是导入工程的事实来源**。索引、运行 DOM、页面摘要、接口关系均为派生数据，可重建，不反向覆盖未知源码。
2. **已有技术栈优先**。识别后让用户确认运行配置，不以“推荐模板”为由重写工程、换框架或替换依赖。
3. **AI 修改可审查**。任何增删改先展示范围及 diff；用户确认后由统一写入流程应用。数据库迁移、发布/推送、生产接口调用须另行确认。
4. **本地优先，不强制平台**。平台不可用不影响本地项目、历史、源码分析，以及仍可连通的自定义 Provider。
5. **明确事实与估算**。识别置信度、创建时间来源、Token 来源、价格来源、余额时效必须可见；未知不等于 0。
6. **默认不共享敏感信息**。Provider Key 不进浏览器、项目导出、日志、记忆或其他 Agent 上下文；平台 Key 永不下发客户端。
7. **并发不等于同时覆盖同一目录**。推理可并发，冲突变更必须隔离并经过合入校验。

## 3. 用户场景与信息架构

### 3.1 关键用户故事

- 作为已有项目的开发者，我选择源码目录后，看到识别出的前端、后端、运行入口及缺失依赖，确认后即可看到真实页面。
- 我选中订单页的“新增”按钮，查看其组件位置和关联接口，让 AI 在按钮旁增加“导出”按钮并调用指定接口。
- 我按“用户/订单/支付”等功能浏览接口，或按创建时间查看新增接口，知道时间是历史推断还是工具内创建记录。
- 我指定在某 Controller/Router 内新增接口，或删除某接口及其调用方，先查看影响再应用。
- 我可以用平台账号选择不同价格的 Provider，也可以完全不连接平台，直接填自己的 Provider。
- 我让三个窗口分别处理页面、接口和测试，随时看见各自进度、Token 和费用，最后受控合入。

### 3.2 桌面端入口

- 工作台：新建项目、**打开文件夹**、**导入源码**、最近项目、Agent 任务中心；“导入源码”中也提供“打开文件夹”选项。
- 项目：概览、代码（只读）、运行预览、接口、设计器、记忆、文档、Git、流水线。
- AI 会话：任务目标、选中元素/接口、上下文、模型路由、diff、运行日志、实时用量。
- 设置：本地 Provider、平台连接、远程配置源、并发/预算、安全、标准备份与旧版迁移。
- 状态栏：当前会话生成速率、缓存命中率、累计 Token、上下文占用；平台已结算金额/可用余额可展开查看。

### 3.3 两条主路径

**导入维护**：打开源码文件夹（直接使用原目录）或选择其他源码导入方式 → 自动静态识别 → 确认信任与运行配置 → 运行前后端 → 选元素/选接口 → AI 生成补丁 → 验证 → 确认合入。

**新建生成**：V1 S1–S7 → 真实运行预览 → 接口索引 → 元素/接口定点维护。两条路径共用 Provider、上下文、计量、会话及安全写入能力。

## 4. 源码导入、识别与运行（V2-SRC）

### 4.1 首批支持矩阵

| 类别     | P0                                                                                  | P1/降级                                                                          |
| -------- | ----------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 源码入口 | 打开本地文件夹（直接使用原目录）、复制源码目录、Git 仓库、普通 ZIP                  | 其他归档格式后续支持，不猜测解压                                                 |
| 前端     | HTML/CSS/JS 静态站点；React+Vite；Vue+Vite；Node workspace 中可独立运行的上述子项目 | Next.js/Nuxt 等 SSR 工程增加专用适配；未知框架可配置运行命令，不宣称源码映射完整 |
| 后端     | Express、NestJS、FastAPI 的显式 HTTP 路由                                           | Flask/Spring/Go 等后续适配；未知项目允许用户提供运行配置与 OpenAPI               |
| 接口契约 | 本地 OpenAPI 3.x 文档及其静态引用；JS/TS 显式 fetch/axios 调用                      | 动态 URL、生成 SDK、GraphQL/RPC/WebSocket 标注未解析/未支持，不强行映射为 REST   |
| 原生工程 | 识别为非 Web 工程，保留既有工具链与生成能力                                         | 不承诺原生控件 DOM 选取                                                          |

矩阵是首批建议范围，不是“自动识别任何工程”的承诺；新增适配器必须附夹具、精确率和降级行为。OpenAPI 外部网络引用默认不自动拉取。

### 4.3 状态与异常

导入任务状态：`selected → scanning → needs_confirmation → preparing → starting → ready`；任何阶段可进入 `failed/cancelled`，重试从可恢复阶段开始。项目已导入和预览已就绪是两个独立状态：缺少运行时不等于导入失败。

ZIP 必须防路径穿越、绝对路径、Windows 盘符/UNC/ADS、大小写碰撞、符号链接越界和解压炸弹；超限在落盘前或流式处理中中止。目录遍历不跟随越过授权根目录的链接。标准源码导出排除密钥、依赖、构建缓存和默认不包含的 `.git`，包含规则可预览但不能修改原文件。

## 5. 运行页面元素选取与源码映射（V2-DOM）

### 5.1 交互规范

在运行预览工具栏提供“交互/选取”模式。交互模式保持业务行为；选取模式悬停高亮、点击选择、Esc 退出，不提交表单、不跳转、不触发删除等业务操作。提供 DOM 树/祖先链替代入口，避免小元素或遮挡元素无法选中。

选中卡片显示标签、可访问名称、必要的 class/id、矩形位置、路由、所属组件候选、源文件及行列、关联接口与映射可信度。密码、输入框当前值、Token、敏感属性默认不采集。

### 5.2 功能要求

| 编号      | 需求与验收要点                                                                                                              | 优先级 |
| --------- | --------------------------------------------------------------------------------------------------------------------------- | ------ |
| V2-DOM-01 | 导入工程运行后可选取原生 DOM；滚动、缩放、响应式断点下高亮正确；选取模式不触发业务事件                                      | P0     |
| V2-DOM-02 | 支持嵌套元素、列表实例、动态新增节点与 SPA 路由；切换路由/重渲染后验证选择是否有效，失效时提示重新选择                      | P0     |
| V2-DOM-03 | 将运行实例与源码节点区分；记录项目/运行实例/页面/组件来源/源码位置/修订信息，不把 CSS selector 当永久唯一 ID                | P0     |
| V2-DOM-04 | 静态 HTML 与 P0 React/Vue 工程建立可验证的源码映射；开发期编译插桩或映射只用于本地预览，不污染生产源码/构建                 | P0     |

### 5.3 安全边界

预览内容视为不可信。禁止其取得 Node、文件系统、Tauri 命令、平台/Provider 凭据或任意 IPC 权限；调试桥只开放选取、尺寸和受限事件。消息校验窗口/运行实例、origin、source、nonce 和结构，拒绝其他页面伪造事件。开发服务跨端口不靠关闭 webSecurity 或全局放宽 CSP/CORS 来解决。

页面文本、源码注释和接口描述是 AI 的输入数据，不是提升权限、执行命令或访问其他项目的指令。

## 6. 接口识别与 AI 定点开发（V2-API）

### 6.1 接口概念与识别证据

“接口”包括后端对外 HTTP 路由和前端 HTTP 调用点；Service 方法作为实现链路节点，不能冒充一个 HTTP 接口。一个接口可以有多个前端调用点，也可能尚未被调用；第三方请求与项目内接口分开展示。

识别证据包括：后端 Router/Controller 声明及挂载前缀、前端调用表达式与 baseURL/代理配置、OpenAPI 契约、用户开启调试后的运行请求。运行时只观察当前受控预览，不主动扫描外部服务。

### 6.2 功能要求

| 编号      | 需求与验收要点                                                                                                                         | 优先级 |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| V2-API-01 | 自动索引后端 method/path/参数/响应/认证线索/源符号，以及前端调用点、页面/组件；合并挂载前缀，区分不同服务中的同名路径                  | P0     |
| V2-API-02 | 以服务、方法、规范路径、契约/调用证据建立关联；统一 `:id` 与 `{id}` 等路径参数，动态拼接/环境缺失/多个候选标记待确认，不能猜成确定关系 | P0     |
| V2-API-03 | 接口列表可按功能分组，支持搜索、标签和未分类；默认优先用户归类，其次契约 tag/项目功能树，再次目录与规则建议；AI 语义归类需授权且计费   | P0     |

### 6.3 创建时间与稳定标识

- 接口持有稳定 `endpointId`；另保存 `serviceId + method + normalizedPath` 作为当前路由身份，路径修改不直接抹掉历史。
- `createdAt` 允许空；`createdAtSource` 为 `tool_event / git_inferred / unknown`，另存 `firstSeenAt`、`updatedAt`。
- Git 时间是“当前可追溯历史中的首次出现推断”，不是客观业务创建时间；文件创建时间、mtime 和最后一次 blame 时间不得冒充接口创建时间。
- 浅克隆、历史改写、文件重命名或符号匹配不可靠时降级并解释；补全 Git 历史须用户同意。
- 未知创建时间的接口置于已知项之后，组内以 firstSeenAt 和 endpointId 稳定排序，并单独标“首次发现”；不将两种时间混用。
- 用户归类和已确认关系在重扫后保留；人工覆盖具有版本和来源。删除对象留历史引用但不继续显示为有效接口。

### 6.4 AI 变更契约

AI 任务输入至少包含：目标项目/工作副本、元素/接口 ID、指定位置、用户目标、选定路由、相关源码/契约、当前基线、允许写集和验收条件。

输出至少包含：变更说明、逐文件补丁、新增/删除接口清单、受影响调用方、迁移风险、测试计划和未解决项。缺乏需求信息时只问必要问题，不自动推断业务权限或支付规则。变更涉及共享组件时允许用户选择实例级或组件级作用范围。

## 7. Provider、模型与运行模式（V2-MDL）

### 7.1 两种连接模式

## 9. 实时指标、价格与账务

### 9.1 用量标准化（V2-USG）

每次真实上游尝试记录：`logicalRequestId`（用户动作）、`attemptId`（一次实际调用）、`providerRequestId`（若有）、会话/任务/项目、实际路由、起止时间、状态、原始 usage 与规范化 usage、价格快照引用。

所有用途都计量，包括代码生成、摘要、记忆抽取、接口 AI 分类、重试、连接对话测试、后台任务和可选子 Agent。仅看聊天框字数不能代表总用量。

| 编号      | 指标/功能           | 定义与验收要点                                                                                                                             | 优先级 |
| --------- | ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ------ |
| V2-USG-01 | 实时 Token 速率     | 默认展示当前生成流近 5 秒输出 Token/秒；只按文本/tokenizer 或上游增量 usage 计算，注明估算/上游实测，不能用 SSE chunk 数替代 Token         | P0     |
| V2-USG-02 | 首 Token 与平均速率 | TTFT 从请求发出到首个有效输出；生成平均速率为输出 Token/首输出至完成时长；排队时间与工具执行时间单列，零时长/无输出显示不可用              | P0     |
| V2-USG-03 | 缓存命中率          | `cacheReadInput / totalInput`；totalInput 含未缓存、缓存读、缓存写且不重复；分母为 0 或无可信缓存数据时显示 N/A                            | P0     |
| V2-USG-04 | 当前会话 Token      | 会话内所有已记录真实尝试的输入+输出累计，包括重发历史消耗；分类展示输入、缓存读、缓存写、输出，估算部分另标，不把上下文大小当累计消耗      | P0     |
| V2-USG-05 | 上下文占用          | 当前会话下一次请求的有效输入/该路由有效窗口，另显示预留最大输出及安全余量；系统提示、工具定义、历史、记忆、文档、工具结果均纳入            | P0     |
| V2-USG-06 | 历史统计            | 按项目/会话/任务/日期/Provider/Model 聚合 Token 与成本；日报缓存命中率用总缓存读除以总输入，不平均各请求百分比                             | P0     |
| V2-USG-07 | 实时刷新与更正      | 流中每秒更新，不支持中途 usage 时标估算；最终 usage 替换同一 attempt 的估算，不再追加一份；断流缺 final usage 标 pending/unknown，支持对账 | P0     |
| V2-USG-08 | 多窗口一致性        | 共享事件流/快照以事件 ID 去重；其他窗口只订阅展示，不重复记录或扣费；重连恢复游标及最终状态                                                | P0     |

规范化至少保留：`totalInput`、`uncachedInput`、`cacheReadInput`、按 TTL 分桶的 `cacheWriteInput`、`totalOutput`、可选推理输出子集、`quality/source`。某协议 input 已含缓存时不得再相加；某协议 input 不含缓存时才补齐。推理 Token 若已包含在输出总数中只能细分展示，不能二次收费。

不支持缓存≠命中率必为 0：只有协议明确报告可解释的 0 才展示 0%。未报告字段不能捏造精度；混合完整/缺失数据聚合显示覆盖率。无法精确分桶但有可靠 input/output 总数时可以展示总数，费用视可用价格和计量维度标为估算/待结算。

上下文分为“已发送实测快照”和“下一请求估算”，不能把上一轮实际输入当作下一轮精确值。切换模型、工具、记忆和压缩历史后重算；超限必须阻止发送或让用户确认精简，不静默丢掉目标源码和需求。

### 9.2 价格优先级（V2-BILL）

对每个**实际调用路由**、调用时间与计费模式，按以下顺序选择：

1. **服务端明确发布且匹配该 Provider+Model 的有效售价**；0 是合法免费价，不等于“未定价”。
2. 没有服务端定价时，使用**该模型身份对应厂商官网的定价**。区分标准/快速/批处理/长上下文阶梯、缓存 TTL 和其他适用维度。
3. 官网没有价格、模型别名无法确认、缺少某项收费维度时显示“价格未知/部分估算”，不能自动按 0 或拿另一 Provider 的价格代用。

“平台价格优先”不意味着把平台渠道 A 的售价套用到用户自建 B；必须匹配可信目录身份。BYOK 的官网价仅为估算依据，第三方优惠、加价或订阅余额以第三方账单为准，不冒充平台实扣。

| V2-BILL-07 | 本地 Provider 余额仅在其提供且用户授权查询接口时显示；否则“不可查询”，允许单独记录人工余额但标明非实时，不混入平台钱包                                    | P0     |
| V2-BILL-08 | 日/月/会话预算及预估费用告警；平台硬限制由服务端执行，本地多窗口预算由共享协调器执行，用户可调整自己的本地预算                                            | P0     |

### 9.3 计算口径与测试样例

对于各输入类别互斥、按百万 Token 定价的路由：

```text
inputTotal = uncachedInput + cacheReadInput + sum(cacheWriteInputByTTL)
consumedTokens = inputTotal + totalOutput
cacheHitRate = cacheReadInput / inputTotal
estimatedTokenCost = (uncachedInput × inputRate
                    + cacheReadInput × cacheReadRate
                    + sum(cacheWriteInputByTTL × cacheWriteRateByTTL)
                    + totalOutput × outputRate) / 1,000,000
availableBalance = postedBalance - activeHolds
```

非 Token 费用（如按次收费工具）独立账单行展示；不在初期支持的收费模式必须拒绝作为可结算的平台路由发布，不遗漏后假称“总账单”。缓存写价格是该桶的完整费率还是基础价的加价必须在价格契约中规范化，公式使用完整费率。

**仅供自动测试的虚构价格**：Provider A 的某模型普通输入 10 元/百万、缓存读 1 元/百万、缓存写 12.5 元/百万、输出 30 元/百万。一次请求普通输入 1000、缓存读 2000、缓存写 0、输出 500，则累计 3500 Token，命中率约 66.67%，金额 `0.01 + 0.002 + 0.015 = 0.027 元`。Provider B 同名模型价格可以不同，必须另算。此示例不是任何厂商实际报价。

### 9.4 平台结算流程

1. 鉴权与路由授权，解析适用价格及计量能力；不能确定安全最大扣费边界的收费模式不接受请求。
2. 根据输入、最大输出、收费工具上限等保守估算预占；在同一事务内检查余额和全局预算。
3. 创建账务请求及幂等映射，转发上游，流式返回内容和不含密钥的计量事件。
4. 收到最终可信 usage 后，以价格快照结算实际费用并释放差额；原账目不删除，修正通过冲正/调整流水。
5. 断流、超时或进程崩溃但上游可能已执行时，标记待对账；不自动重发同一未知执行状态请求，也不永久冻结且无处理入口。
6. 对账任务按上游查询能力处理；无查询能力时进入有时限和审计的人工处理队列，用户可见。完成后客户端和网站读取同一账本结果。

官方价格回退若用于平台实扣，必须先由服务端发布可结算的核验快照和币种规则；无可靠价格或计量时阻止该路由的新平台请求。不能由客户端临时抓官网结果决定收费。

## 10. 多窗口 Agent 并发（V2-AGT）

### 10.1 对象与界面

窗口是视图，Session 是对话与上下文，Task 是一次工作目标，Run/Attempt 是执行与计费。多个窗口观看同一 Session 只能产生一个运行实例；不能因重开窗口重发模型请求。

每个 Agent 可选不同 Provider+Model、工作项目、任务目标和预算。任务中心显示排队、运行、等待确认、测试、待合入、冲突、失败、完成、取消。窗口标题显示项目/任务，日志、选择状态和流式输出不串会话。

### 10.3 状态、租约与恢复

建议任务生命周期为 `queued → running → awaiting_confirmation → validating → ready_to_merge → merged`；包含 `failed/cancelled/conflicted` 分支。只读任务可从 validating 直接 completed。产品状态映射到现有状态机时统一契约，不在不同外壳私自增加不同含义的状态。

协调器的锁必须在进程间生效，并绑定 workspace/data-profile、owner、lease expiry 与 fencing token；过期进程即使恢复也不能继续写。文件应用使用持久化变更日志、快照和失败补偿；“单文件原子替换”不等于多文件事务原子性。回滚须验证当前内容仍属于本任务，否则进入冲突处理而非覆盖后续修改。

建议同一数据域只能有一个活动协调器；其他 Electron/Tauri 实例连接它或以只读视图打开。无法安全接管时明确拒绝第二个写协调器。

## 13. 迁移与兼容

1. **原项目不转换源码**：既有项目和设计 DSL 原地可读；导入的新源码不强制生成 DSL。首次升级先备份本地元数据库，再做可回滚迁移。
2. **取消专有格式新生产**：主导入入口改为源码；新导出/定时备份生成普通目录或 ZIP。源码、记忆 JSON/JSONL、文档 Markdown/原件可分别导出；可选元数据不影响源码运行，源码导入不得要求其存在。
3. **完整数据恢复单独命名**：标准 ZIP 可包含可读元数据以恢复备注/会话/记忆；“恢复 EveryoneCoding 本地数据”与“导入源码”是两个流程。恢复支持预览冲突，默认不覆盖；密钥需重新配置。
4. **旧 `.ecpkg` 一次性迁移**：独立工具/入口读取现存旧包，在新目录导出普通源码和公开数据文件；保留旧包，不新增专有写入。加密旧包需用户密码，失败不产生半解密结果；完成后用标准源码流程验证。
5. **现存备份任务**：升级时提示迁移至普通目录/ZIP，不静默继续写 `.ecpkg`，也不自动删除旧备份。专有增量/签名/加密规则不延续为新的源码导入协议。
6. **Provider/账务迁移**：按真实外键迁移复合身份；不能还原的历史单独标识。历史估算不自动转成真实债务，不追溯扣平台余额。
7. **旧索引可重建**：旧锚点重新校验，失效状态可见；用户备注/记忆不因重扫被删除。索引中间态不能触发 AI 自动覆盖源码。
8. 旧测试的业务保障保留，但“导出文件必须是 `.ecpkg`”等与 V2 冲突的断言需替换；旧包 reader 回归保留，不能只删测试掩盖迁移缺失。

### 14.2 门禁

- 每项 P0 需求至少映射一个自动测试或可复现端到端场景；未支持框架和 P1 项不得混写为完成。
- 价格/计量/账务用固定夹具做精确断言；跨进程锁、磁盘写入和数据库并发必须有真实资源测试，不能全靠内存假实现。
- UI 必须经过浏览器或真实桌面窗口操作验证；原生窗口、IPC、工作副本和宿主进程必须分别验证 Electron/Tauri，不以浏览器 mock 代替。
- 真实模型及收费请求需要明确测试预算；受控流夹具可验证流程，但报告区分“模拟上游通过”与“真实 Provider 验证”。
- 执行仓库当前适用的 lint、typecheck、测试、格式和构建门禁，保留命令/结果/环境。已有失败、环境阻塞、新增回归分开记录，不能把未运行写为通过。
- PRD 和任务文档只描述目标，不将旧测试数量当作 V2 已完成证据。
