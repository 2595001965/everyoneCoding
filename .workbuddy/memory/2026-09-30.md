### 修掉的真缺陷

1. **真机 OCR 从未跑通过**：识别脚本用了不存在的 `[Windows.Globalization.Language]::CreateLanguage`，
   每张图都会失败；09-23 只跑过可用性探测（probe），没跑过识别。改为
   `New-Object Windows.Globalization.Language '<tag>'`，并新增真机集成测试
   `packages/core/src/docs/__tests__/windows-ocr.integration.test.ts`（System.Drawing 现场渲染文字图 →
   真实 OCR → 入库 → 检索；引擎不可用时 skip 并打印原因）。**教训：探测通过 ≠ 识别可用。**
2. **缺省语言 zh-CN 对不上识别器**：本机识别器标签是 `zh-Hans-CN`，`TryCreateFromLanguage('zh-CN')` 返回 null。
   新增 `resolveOcrLanguage`（简繁不互相顶替，其余按主子标签），端口内缓存解析结果。
3. **中文 OCR 文本检索不到**：WinRT 对中文逐字成"词"，按空格拼出「发 票 编 号」。新增 `joinOcrWords` 去掉相邻 CJK 字符间空白。
4. **段落聚合把每行切成一段**：`y` 是行框上沿，原来用"上沿差 > 0.9 行高"判分段，正常行距恒成立。改为"下沿到上沿的间隙 > 0.8 行高"。
5. **空壳文档入库**：扫描件 PDF / 空 Markdown 解析出一个空段落就入库成「未命名文档」。现在统一 `empty_content`，
   PDF 提示改用图片 OCR；DOCX/PDF 解析异常统一包成 `parse_failed`（域层 → INVALID_ARGUMENT，原因可读）。
6. **OCR 语言选了没用**：`importFromFile` 收了 `ocrLanguage` 却没往下传；文件名也没传（OCR 标题恒为"图片文档"）。

### 只有真实安装包才暴露的坑（都已修）

1. 外壳 `process.spawn` 的子进程随应用退出被清理 → 回滚安装包必须 `Start-Process` 独立拉起。
2. Tauri 插件 `on_before_exit` 里 `block_on` 会 panic；panic 断开 IPC 后前端改走 postMessage **重发同一命令**。
3. Tauri 应用退出后 exe 仍被锁 ~5s → NSIS `NSIS_HOOK_PREINSTALL` 等 exe 可写，否则被动安装器卡在"重试"对话框。
4. 两种 NSIS 都经 Shell 以用户身份重启应用：进程级环境变量（`EC_UPDATE_URL` / `EC_ELECTRON_USER_DATA_DIR`）传不到新版本。
5. electron-updater 会复用 pending 里已校验的包不重下；差分只拉变化块，"翻中间一个字节"的篡改可能根本没被下载。
6. `build/installer.nsh` 曾被 `.gitignore` 的 `build/` 吞掉从未入库（Electron 打包必失败）→ 已反选。
