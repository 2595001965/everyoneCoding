- 表现为**prettier 结果非确定性**：连续运行每次报出的不合规文件都不同
  （3 个 → 5 个 → 6 个，且集中在对方正在写的 account 网关模块），中间态被检查撞上。

不要把别人的半成品一起 `--write`，会造成冲突并可能破坏其正在写的代码。**
只对自己触碰过的文件做格式化与验证。

### 重要发现：6 个包在 CI 里是「假绿灯」，共 49 个测试文件从未执行

CI 日志里 `packages/registry test: No test files found, exiting with code 0`——
**这不是通过，是根本没跑**。根因：这些包**没有自己的 `vitest.config.ts`**，
`vitest run` 向上找到根配置，而根 `include` 是仓库根锚定的
`['{packages,apps}/*/src/**/*.test.{ts,tsx}']`；从包目录跑时这串 glob 对不上 → 0 文件 →
`--passWithNoTests` 静默退出 0。**用 `npx vitest run <子串路径>` 从根跑是能找到它们的**
（我实际验证过），所以本地易误判"测试都在跑"。

受影响包与文件数：`packages/registry` 8、`package-kit` 18、`preview` 13、`pipeline` 7、
`git` 2、`account` 1。

修复：按 `packages/memory|core/vitest.config.ts` 的既有约定，为 6 个包各补
`vitest.config.ts`（`environment:'node'`、`include:['src/**/*.test.{ts,tsx}']`、`restoreMocks:true`）。
`packages/git` 单独放宽 `testTimeout: 180000`—— 其 `git-integration.test.ts` 单例实测 82s
（真实起 git 进程跑 init→commit→merge→push），15s 默认预算必红。

补完后逐包在**包目录内**验证确实执行了：registry 5文件/75、preview 12/96、pipeline 6/65、
account 1/30、package-kit 16/104、git 2/56 —— **共 696 项全绿**（含 git 集成真跑）。
注意 `test:coverage` 脚本与 `test` 共用同一份 config，故覆盖率门禁的同一盲区一并闭合。
