### 一个必须解释的设计决定：代码根登记

端口契约里 `targetDir` 是**用户必填的「克隆目录」**（UI 文案与 placeholder 都是这个意思，且为空时提交按钮禁用），
意味着仓库可能落在工程目录之外。而 `WorkspaceLayout` 约定要求代码在 `<projectDir>/code`。

两条路都试过取舍：
- **目录联接（junction）指向用户目录**：`purgeProject` 会 `rmSync(projectDir, {recursive:true})`，
  Windows 上递归删除会**穿过 junction 删掉用户仓库本身**——不可接受，弃用。
- **登记文件（采用）**：`<projectDir>/meta/code-root.txt` 存绝对路径；
  读取时校验目录存在（用户可能删掉/移动），不存在则退回 `<projectDir>/code`。
  导出（`listCodeFiles`/`readCodeFile`/`listObjects('code')`）与复制（`duplicateProject`）都走 `resolveCodeRoot()`。

**没改冻结的端口契约**，也没让用户的目录选择落空。

### 另一个真机上会炸的 bug（已修）

`AuthApi`/`WorkspaceApi.importFromGit` 的 `onProgress?: (ratio, message) => void` 是**函数**，
而 `domain-ports.ts` 直接把它塞进 `params` 跨 IPC 发送——
Electron 结构化克隆会抛 `An object could not be cloned`，**调用根本到不了主进程**。
此前域未装配，这条路径没人走过，所以一直没暴露。
已修：适配器里剥离 `onProgress` 再发（`const { onProgress: _dropped, ...cloneable } = input`）。
**代价**：克隆进度目前不上报（域 RPC 是请求/响应，没有进度事件通道），界面按钮保持 loading、完成后一次性出结果。
要补进度需另加一条事件通道，属后续增强。

## 域事件通道已落地：克隆进度改为事件推送（收掉上午那条"后续增强"）

上午留的「要补进度需另加一条事件通道」已做掉。范围是**通用能力 + 首个消费者**，不是只给 Git 导入打补丁。

### 契约（`packages/shell-api/src/domain-control.ts`）

- `DomainEvent`：`{ requestId, domain, payload }`。**事件不带自有 id**，一律复用触发它的请求 id。
- `DomainEventSink` + `createDomainEventSink()`：requestId → 发送器注册表；无订阅者静默丢弃，目标抛错不外传。
- `DomainControlHost.onEvent?`：**可选能力**。Tauri / mock 不提供，渲染层退化为"无过程反馈"而非调用失败。
- `DomainControlServiceHost.events`：主进程侧注册表（IPC 按 requestId 注册 `event.sender`，`finally` 注销）。
- 载荷：`workspace:import-progress` + 三阶段 `clone|inspect|finalize`，`ratio` 在不可知阶段为 `null`；
  `isWorkspaceImportProgressEvent()` 做跨进程守卫（type/stage/message 形状 + ratio 必须 0-1 或 null）。

### 接线（一条链，六处）

| 处 | 改动 |
| --- | --- |
| 通道 | `ec:domain:event`（进 `EVENT_CHANNELS`，无 handler，纯单向） |
| runtime | `DomainRouter` 加第三参数 `ctx: { requestId, emit }`；**信封的 requestId/domain 由 runtime 补齐**，域实现只给载荷 |
| 主进程 | `ipc/domain.ts` 在 invoke 期间注册 `event.sender`、`finally` 注销；`workspace.ts` 的 importFromGit 三阶段 `ctx.emit` |
| preload | `domain.onEvent(listener)`；只校验形状并原样回调，**过滤留在渲染层**（域调用可能并发） |
| bridge | Electron `ShellHost.domain.onEvent` 适配；Tauri 不实现（`onEvent` 可选） |
| 渲染层 | `createDomainCaller.call(…, requestId?)` 支持显式 id；`createWorkspaceApi(call, subscribe)` 里按 id 过滤 + 请求定局即退订 |

UI：`NewProjectDialog` 有比例显示百分比、无比例用 `Progress indeterminate`——**不假装 100%**。

### 三个踩到的坑

1. **`DomainRouter` 加参数会打断既有断言**：`domain-runtime.test.ts` 的 `toHaveBeenCalledWith('m', params)`
   要补 `expect.anything()`；`domain-settings.test.ts` 两处直连 router 的调用要补 ctx（加了 `DIRECT_CTX` 常量）。
   *顺带发现*：直连 router 会绕过错误码映射与脱敏，只应在"绕过 runtime 单独问一次实现"时用。
2. **RTL 里同步 `act(() => setState(...))` 不 flush**：进度断言必须先 `getByText` 失败过。
   改 `await act(async () => …)` + `findByText` 才稳。
3. **`getByText` 的 `normalizeWhitespace` 会折叠空白**：git 原始行里的双空格（`Receiving objects:  42%`）
   统一改用单空格文案，避免断言依赖空白细节。
