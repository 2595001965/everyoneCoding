## D09 交付

- API 工作台可对现有接口发起扩展或删除，并可选定 Router/Controller/父符号新增接口；页面功能可从已解析调用点发起。DOM 检查器可从已附加的运行元素建立定点功能目标，保留 element/source revision、页面、符号、作用域、插入位置及共享组件确认。
- API 目标类型从 registry 导出，经 renderer 路由状态进入原 CodePage；主进程重新解析目标而不信任 renderer 提交的路径。目标携带当前 endpoint revision、源码证据/哈希、精确调用方以及契约、测试、文档和锚点影响文件；D07 plan 还记录预期读哈希和共享资源。显式选择“当前工作树”才允许当前基线；删除需确认影响并完整选择目标文件；迁移/DDL 另行确认。
- CodeAgent 仍调用原上下文组装、生成/续写和 WritePipeline。只校验指定写集内的最小差异，不提供手动源码写入口或整页重生成替代项。AI 输出计划前在隔离补丁 overlay 上真实重扫 API：新增路由必须精确解析，删除路由与所有已知本地调用都须消失，扩展须保留目标路由，依接口功能须保留目标 API 及目标页面调用。扫描不完整、目标陈旧、路由重复、调用方遗漏或 DOM hash 变化均拒绝计划/合入。
- 安全合入后重扫接口索引，并且只更新已经存在且能精确匹配的页面/功能记忆；删除接口只从已有关联功能记忆中移除相应 API 清单条目，不伪造新记忆。索引刷新失败会显示“源码已合入但刷新失败”提示，不虚报事务回滚。
