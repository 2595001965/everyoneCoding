### 新增的环境坑（已同步进 MEMORY.md）

- **经 pnpm 转发的命令必须把 nvm v24 目录放进 PATH 前缀**。只把 `node.exe` 的绝对路径喂给
  `pnpm.cjs` 没用：脚本本体由 pnpm 重新 spawn，子进程里裸 `node` 会解析到 WorkBuddy 托管的
  v22.22.2（ABI 127），而 better-sqlite3 是按 ABI 137 构建的 ⇒ `pnpm test:e2e` 首轮 7 项全红，
  全是 `NODE_MODULE_VERSION 137 ... requires 127`，看起来像代码坏了。
- **根级全量单测最稳的跑法是串行**（`-r --workspace-concurrency=1 test`）。并发跑除了 §5.1 的基准
  假红外，`@ec/renderer` 里几条时间敏感用例（`pipeline-workspace` 6.7s、`rename-dialog` 11.8s）
  也会因 CPU 争用超时；我一边跑全量一边跑 `tsc` 就踩到过一次，单独复跑两次均全绿。
- **`pnpm -r test` 会在第一个失败的包停下**（`ERR_PNPM_RECURSIVE_RUN_FIRST_FAIL`），
  后面的包根本不跑 —— 只看尾部输出会误判成"全绿"。
