## git 用例 8 项失败：确诊为环境性，已消失（当日第三轮）

首轮全量单测有两文件共 8 项红，全部是 `git` 真实子进程用例超时。**不改测试超时预算**，
改为确诊根因。

### 决定性实验（比只量 `git --version` 更有判别力）

| 被测量 | 退化期间 | 恢复后 |
| --- | --- | --- |
| `spawn where.exe git`（极简原生进程） | — | **501ms** |
| `spawn node -e 0` | — | **503ms** |
| `spawn git --version` | **26489ms** | **759ms** |
| `git --version`（精简 env） | — | 861ms |

→ **进程创建本身就有 ~0.5s 地板价**，git 只多约 260ms。退化期间 `git --version` 26.5s
说明**进程创建被系统层拖慢约 50 倍**（实时杀毒/过滤驱动），与 git 及本仓代码无关。

### 已排除代码侧原因

- `@ec/git` 无冗余子进程：`probe()` 只在建客户端时跑一次；`status()` 单次 spawn；
  `unstage` 的 `headSha + rm --cached/reset` 是必要两步；后端探测结果被 ESM 模块缓存。
- 两个红文件未引用 T12-01 改动的任何模块。

### 结果

环境恢复后按**默认超时**（未加 `--testTimeout`）复跑：

- `domain-workspace-git.test.ts` **9/9**，46.2s（单例 2.3–8.3s）。
- `git-integration.test.ts` **3/3**，184.9s（CLI 106.0s + git2 78.7s）。
- 全量单测 **236 文件 / 2419 项全绿**，215.9s（原为 513.5s）。

结论与四步自证流程已写入 `docs/TEST-REPORT.md §1.2`（含"同时量 `where.exe` 与 `git --version`"
这一改进的判据），并把这几条口径回填进本仓 `MEMORY.md` 的「本机命令」节。

   `element_id`/`body` 必抛"列不存在"。迁移 `0006_designer_notes.sql` 补齐列，
