## T12-05 归档、用量、备份与遥测生产接线

把 `package` / `usage` 两域从"挂上路由表"推进到"真实可用"，修掉 5 处生产级缺陷。

### 修掉的真实缺陷（按危害排序）

1. **`setting` 表列名不匹配（生产必炸）**：`usage-domain` / `package-domain` 写
   `SELECT value FROM setting`，真实列是 `value_json`（迁移 0001），`user_id` NOT NULL。
   用户点「预算」或「定时备份」必抛 `no such column: value`。已全部改走 `createSettingStore`。
2. **预算从未进入 AI 网关**：面板写 `setting` 表，`createAiStack` 用 `DEFAULT_BUDGET`（不限），
   两侧互不相干 ⇒ 「配了预算还在烧钱」。现 `readPersistedBudget` 装载注入 +
   `usage.setBudget` 经 `onBudgetChanged` 回灌运行中的 `BudgetGuard`。
3. **遥测零生产调用点**：`@ec/core` 的遥测三件套完备但无人调用。新增
   `domain/telemetry-runtime.ts`（默认关闭 / 白名单 / 三层清除），导出导入接入埋点。
4. **自愈整体 `NOT_SUPPORTED`**：package-kit 四模块齐备，主进程直接拒答。现接
   `code_anchor` + `memory_doc_link` + 附件目录三处真实数据源。
5. **附件恒为空数组**：`listAttachments()` 返回 `[]` 却宣称支持附件 = 静默丢弃。
   现按内容寻址真实枚举（`<projectDir>/attachments/<sha256>.<ext>`）与落盘。

### 关键设计决定

- **预算两侧共用一份落点**：`setting.usage_budget` 键，`createSettingStore` 是唯一读写入口。
  运行时变更必须即时回灌网关（否则要等重启，用户看到"改了没反应"）。
- **遥测清除必须三层**：内存队列 + 文件缓冲 + 数据库记录。缺一层就是没清干净；
  数据库层即使本仓库不落库也显式尝试清理历史遗留表。
- **附件归属判定**：内容寻址天然跨项目去重，导入时按"哪个项目的文档引用了该文件名"定位；
  无法判定时落到 `__attachments__` 暂存目录，**绝不丢内容**。
- **`AiStackHandle` 契约**：`@ec/shell-api` 新增，主进程经 `aiRuntime.handle` 传给域工厂。

## T13-01 Tauri 双形态功能等价（经受控侧车承载业务运行时）

### 方案（否决了"迁进 Rust"）

- 业务逻辑（15 域 + AI 栈 + `@ec/*` 内核 + better-sqlite3）全在 Node 侧；迁 Rust = 重写第二遍。
  采纳 **受控 sidecar**：Rust 只做生命周期 + 协议搬运 + 宿主能力。
- 前提成立的原因：**全仓只有 2 个文件 `import 'electron'`**（main/index.ts、preload/index.ts），
  域模块全部依赖注入。故抽 `main/runtime/bootstrap.ts`（`createHeadlessRuntime`）后，
  Electron 与侧车共用同一份装配。

### 新增/改动落点

- Node：`src/main/runtime/bootstrap.ts`、`src/sidecar/{protocol,link,service,paths,index}.ts`、
  `scripts/build-sidecar.mjs`（产物 `dist/sidecar/everyone-coding-sidecar.cjs` + `sidecar-manifest.json`）。
- Rust：`src/sidecar/{mod,protocol,tests}.rs`、`commands/domain.rs`、`commands/ai.rs`（真实现）、
  `lib.rs`（manage + `RunEvent::Exit` 收尾）、`secure_store.rs`/`external.rs` 提升为 `pub(crate)`。
- TS 桥接：`apps/desktop-tauri/src/bridge.ts` 实现 `ai`/`domain`（含事件总线）。

### 踩过的坑（都已被测试钉住）

1. **订阅建立前全部退订 = 永久泄漏**：`sidecar_subscribe` 异步返回；若 promise 解析前退订，
   `sidecarSubId` 仍 null，释放分支不成立。修法：订阅返回后立刻判空释放。
2. **装配期间宿主退出 → 新建 runtime 无人释放**：`finish()` 已 settled，`createRuntime` 才返回。
   修法：装配返回后检查 settled 并立刻 dispose。
3. **宿主能力应答取值**：结构化对象被当裸值取 ⇒ 会变成"加密成功但密文为空"的静默损坏。
   修法：`fieldOf()` 显式取字段，取不到即抛。
4. **`ai.stream` 只回 `accepted:false`** ⇒ 界面永远转圈。必须补 `error` + `done` 两条事件。
5. **侧车 stdout 必须只含协议帧**：入口先把 console 全部改道 stderr（领域代码有 console.info）。
6. **harness 关入站管道 ≠ 测试结束**：协议里"stdin 关闭"就是"宿主已死"，侧车会拒绝再写帧
   （ready 被吞）。测试要模拟宿主消失只能用 `closeHost()`。

### 协议要点（改一处必须两侧同改）

- NDJSON over stdin/stdout；判别字段 `t`：hello/welcome/ready/req/res/evt/host/hostres/bye。
- **DPAPI 由宿主提供**：侧车经 `secure.encrypt`/`secure.decrypt` 回传 Rust 执行，
  复用 `secure_store.rs` 同一份 DPAPI。故 `SafeStorageLike` 的原语放宽为 `Buffer | Promise<Buffer>`，
  下游三处存储只多一个 `await`，落盘布局与 Electron 一字不差。
- 字段名一律 camelCase（`secureStore`/`syncDomains`/`dataDir`）；Rust 侧有真实 JSON 文本级单测钉住。
- op/capability/event 名两侧逐字一致，Rust 单测里有硬编码比对。
